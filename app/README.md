# MLaud — приложение (Swift)

Главное окно в дизайн-системе Niti плюс строка меню. Окно: сайдбар с разделами
(Обзор, Записи, Суфлёр, Голоса, Диктовка, iPhone, Уведомления, Настройки), экраны на SwiftUI
внутри AppKit-оболочки. Строка меню остаётся как статус и быстрые действия. Собрано на SwiftPM
(без Xcode-проекта), минимальная macOS — 15.0 (ADR-020).

## Структура

- `Sources/MLaudCore/` — тестируемая логика без UI:
  - `FolderStore`, `SettingsStore` — папка inbox и настройки (UserDefaults).
  - `InboxScanner` — готовые аудиофайлы в папке и те, что ещё едут из iCloud.
  - `WorkerCommand` — запуск `python -m mlaud_worker…` с окружением.
  - `ProcessingStatus`, `OverviewState` — состояние конвейера и правила показа Обзора.
  - `RecordingIndex` — архив транскриптов: `.meta.json`, дата из имени файла, сайдкары
    разметки голосов, итоги суфлёра.
  - `NotificationHistory`, `PhoneReceipts`, `SpeakerSidecar`, `VoiceListing` — журналы и сайдкары.
  - `AudioCapture`, `HotKey`, `TextInserter`, `DictationProtocol` — диктовка; `ChannelCommand`,
    `RecognizerEvent` там же — канальный протокол звонка.
  - Суфлёр, этап 3 («живой звонок без модели»): `CallSession` (машина состояний экрана),
    `LiveTranscript` (лента и `transcript.live.jsonl`), `CallRecord`/`CallStore`
    (`~/ASR/Prompter/calls/<call_id>/call.json`), `CallTracks` (выравнивание каналов по времени
    звонка), `CallRecorder` (сайдкар `.channels.json` → `.incoming/<id>.pcm` → `.m4a` в inbox,
    `recover` после краха), `ChannelsSidecar`, `AudioPCM`, `AppAudioPolicy`, `OutputDevice`.
- `Sources/MLaudApp/` — оболочка и экраны:
  - `AppDelegate` — строка меню, процессы (worker, распознаватель, приём с iPhone), слежение
    за папкой; заполняет `AppModel` и исполняет `AppCommands` для экранов.
  - `MainWindowController` — окно + `NSHostingView`, главное меню. Приложение всегда в Dock;
    закрытие окна его не завершает, клик по иконке открывает окно снова.
  - `AppModel`, `SettingsModel` — наблюдаемое состояние; настройки применяются сразу,
    побочный эффект — по ключу (смена токена не перезапускает модель диктовки).
  - `Screens/` — экраны разделов и витрина компонентов (⌥-клик по «Настройки»).
    `PrompterScreen` — список звонков; `CallScreen` — экран звонка по фазам
    (готов → идёт → завершение → готово), статусная строка с уровнями каналов.
  - `CallController` — клей звонка: микрофон (`AudioCapture`) + звук приложения
    (`AppAudioCapture`, ScreenCaptureKit) → `CallRecorder` и резидентный распознаватель
    (`RecognizerProcess`, общий с диктовкой; во время звонка диктовка недоступна).
    Создаётся при первом «Суфлёр: начать звонок…», не при запуске и не в `--screenshot`.
  - `VoicesModel` + `VoicesRunner` — состояние раздела «Голоса» и запуск
    `python -m mlaud_worker.voices`; экран — `Screens/VoicesScreen.swift`, подписи и плашки —
    `VoicesPresentation` в Core (с тестами).
- `Sources/MLaudTests/` — тест-раннер без XCTest (XCTest нет в Command Line Tools). Свои
  домены defaults `mlaud.test.*` он сметает при старте и в конце: cfprefsd дописывает пустые
  plist уже после выхода процесса, так что до следующего прогона в `~/Library/Preferences`
  остаётся до десятка пустых файлов.
- Дизайн-система — общий пакет `NitiUI` из `../mlaud mobile/DesignSystem` (ADR-019).

## Сборка и запуск

```bash
swift build                 # собрать
swift run MLaudApp          # запустить (иконка в строке меню → «Открыть MLaud»)
swift run MLaudTests        # прогнать тесты
swift run MLaudApp --screenshot ~/ASR/spikes/ui-shots   # снимки всех разделов в обеих темах
./build-dmg.sh              # MLaud.app + MLaud.dmg с вложенным Python-окружением
```

Дымовая проверка раздела «Голоса» — реальный worker на копии сайдкаров во временном каталоге
(`assign --none` меняет файлы, поэтому не на `~/ASR/service/speakers`):

```bash
./smoke-voices.sh           # фикстура из двух записей + swift run MLaudApp --smoke-voices …
```

Сам режим: `swift run MLaudApp --smoke-voices <каталог speakers> <python> <каталог worker>
<каталог базы голосов> [<каталог результатов> <архив аудио>]`. Ожидает в
`<каталог speakers>/<период>/<запись>/speakers.json` хотя бы один кластер «к разметке»;
печатает состояние до и после «оставить без имени», рендер экрана, переход из образца к
карточке (и в другую запись с теми же метками) и выходит с 0, если всё сошлось (2 — размечать
было нечего). С двумя необязательными хвостовыми аргументами (`cfg.output` и `cfg.processed`
worker'а) после этого проверяется и «Разметить заново → Всё без сайдкара»: индекс результатов даёт
кандидатов (готовы / без аудио), подтверждение отвечает «да» печатью, очередь гонит
реальный `prepare` с реальными моделями (из локального кеша HF, `HF_HUB_OFFLINE=1`) и в конце
сверяется, что сайдкар появился, транскрипт перезаписан, ошибок нет, `onChange` дёрнут и
после пересканирования готовых кандидатов не осталось. Worker при этом пишет только во
временный корень: `MLAUD_OUTPUT`, `MLAUD_PROCESSED`, `MLAUD_SERVICE`, `MLAUD_VOICES_DIR`.
Пять хвостовых аргументов (забыт архив) — ошибка, код 64: массовая разметка не пропускается молча.

Режим `--screenshot` не запускает слежение, диктовку и приём: рядом может работать
установленное приложение на той же папке. У dev-запуска свои defaults; папку для Обзора
можно подставить переменной `MLAUD_INBOX`, папки звонков суфлёра — `MLAUD_PROMPTER_DIR`
(по умолчанию `~/ASR/Prompter/calls`). Экран звонка снимается на подставном состоянии
(`3a-prompter-list`, `3b-call-ready` … `3e-call-done`), контроллер звонка при этом не создаётся.
Dev-пути к Python и worker'у — `MLAUD_PY`, `MLAUD_WORKER_DIR` (по умолчанию `poc/.venv` и
`worker/` в репозитории).

## Суфлёр — состояние

Этап 3 плана (`docs/task-app-ui-and-prompter.md` §6): живой звонок без модели подсказок.
«Суфлёр: начать звонок…» → чек-лист (микрофон, звук приложения, наушники) → «Старт» →
лента транскрипта двух каналов → «Стоп» → `<call_id>.m4a` + `<call_id>.channels.json` в inbox,
дальше обычный конвейер (worker размечает каналы как «Я» / «Собеседник» без диаризации).
Папка звонка: `call.json`, `transcript.live.jsonl`. Брифы, карточки подсказок, итоги — этап 4.
Известные ограничения: устройство ввода — системное по умолчанию (без выбора на экране);
кандидаты на захват звука — только приложения с окнами; согласие «Запись экрана» действует
после перезапуска приложения; запись `.incoming/<id>.pcm` лежит в inbox (в iCloud, если inbox
там) и после краха доделывается при следующем запуске. Сборка `.dmg` — 0.11.0.

## Строка меню

Статус · iPhone (если включён) · **Открыть MLaud** · Обработать сейчас ⌘R · Суфлёр: начать
звонок… (во время звонка — «звонок mm:ss — Стоп») · Диктовка · Уведомления… · Настройки… ⌘, ·
Выход. Иконка во время звонка — `waveform.badge.mic`. В главном меню ⌘R контекстный: в разделе
«Суфлёр» — старт/стоп звонка, иначе «Обработать сейчас». Всё остальное — в окне (ux-app.md §5).
