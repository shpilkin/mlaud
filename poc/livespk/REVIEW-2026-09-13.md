# Ревью архитектуры суфлёра (этапы 3–5, код 0.13.6). 2026-09-13

Четыре независимых ревьюера (захват и офлайн-путь в Swift; живой путь воркера; подсказчик;
документы против кода) + два состязательных проверяющих на каждую находку (22 находки,
18 подтверждены двумя голосами; 4 помечены «опровергнуто», хотя оба проверяющих в тексте
воспроизвели дефект запуском; для двух из них (14, 15) я сам прочитал `_lose_turn`/`_after_flight`
и `estimate_cost` — механизм ровно такой, как описан; 10 и 20 совпадают с замером RESULT.md).
Планка находки — из CLAUDE.md: есть конкретный вход, при котором код даёт неверный
результат, падает или теряет данные. Код не менялся. Спайк по «Я / не я» — [RESULT.md](RESULT.md).

## Оценка в целом

- **Подсказчик (воркер + PrompterController)** сделан добротно: однопоточный оркестратор с
  подставными часами, стабильный префикс system-промта под кэш, стриминговый разбор карточек,
  фолбэк `response_format`, ключ только через env и redact в логах. Слабости — жизненный цикл
  (состояние живёт весь сеанс приложения) и машина повторов.
- **Зависимость от атрибуции — тотальная.** Ход стреляет только по каналу `them`
  (`PrompterController.swift:160`, `CallController.swift:135`), содержимое хода — все строки
  с метками (`prompt.py:58`), роль велит отвечать собеседнику. Ошибка «Я → не я» = суфлёр
  отвечает на слова самого пользователя (реальный журнал 16-48-37: все 8 реплик одного
  говорящего ушли «не я», ходы 1–6 — до того, как заговорил собеседник); «не я → Я» = молчит.
  Уверенность пометки (`voice.score`) модели не передаётся — только в журнал.
- **Офлайн-путь в Swift** — тонкий клей над ВКС-путём, маршрутизация чистая и покрыта тестами,
  но тракт захвата непрозрачен: режим микрофона не читается, сторож здоровья по RMS считает
  гейт с нулями здоровым, смещение канала при `open` захардкожено 0.
- **Живой путь воркера** структурно слаб для «кто говорит на одном микрофоне»: эмбеддится
  сырое окно VAD (пауза + речь + хвост ≥ 0.8 с), одна метка на окно до 18 с без сегментации
  смены говорящего, одноклассовый порог, снятый для одного центроида, применяется к
  максимуму по N образцам.
- **Документы** переносят цифры S4 (71 % / 0 ложных / порог 0.60 / «2 с») как свойства
  живого маркера без замера в его конфигурации; приёмка этапа 5 по `transcript.live.jsonl`
  сейчас неизмерима (см. находки 2, 15, 17, 18).

## Находки: захват и офлайн-путь (Swift)

1. **[high]** `CallController.swift:596` — офлайн открывает канал с `offset: 0` вместо
   `recordedFrames / sampleRate`: запись идёт с `start()`, звук в распознаватель — только после
   `ready`; при холодном процессе (первый звонок, > 5 мин без диктовки) все `t0/t1` ленты и
   журнала отстают от `.m4a` на время загрузки модели; после перезапуска распознавателя время
   начинается с нуля заново. Правка: смещение как в ВКС-ветке, из `recordedFrames`.
2. **[high]** `LiveTranscript.swift:78` — `encodeLine` дописывает `,"voice":…` **после**
   закрывающей `}`: каждая офлайн-строка с пометкой в `transcript.live.jsonl` — не JSON (на
   диске: `{"ch":"them",…,"text":"…"},"voice":0.16`). Ломает любой разбор журнала для
   приёмки. Правка: поле внутрь объекта; тест на `JSONSerialization` по строке.
3. **[medium]** `LiveTranscript.swift:52` — фраза, ушедшая в `them`, сбрасывает поколение
   `them`, а `commit/preview` приходили в `me`: текст собеседника копится в сером хвосте под
   «Я». Правка: сбрасывать поколение физического канала, а не логического.
4. **[medium]** (= 12) `PrompterController.swift:141` / `CallController.swift:180` — `relabel` уже
   отправленной строки не доходит до модели: `fire()` берёт только `id > lastSentID`, ход без
   реплик воркер отбрасывает; `me`-relabel не шлётся вовсе. Правка: ход с явным списком
   исправлений (`relabel` в протоколе подсказчика) или пересылка строки с новым id.

## Находки: живой путь воркера

5. **[high]** `livevoice.py:50` — счёт = `max` по всем образцам «Я», порог 0.60 снят в S4 для
   одного центроида; per-sample гейта нет (`self_refs` грузит любой `.npy`). С образцом,
   снятым из окна с нулями, окно собеседника «3 с речи + 5 с нулей» → «Я». См. RESULT.md §3.
6. **[high]** `livevoice.py:45` — `MIN_SEC = 2` проверяется по длине окна, а окно = вся
   тишина от закрытия прошлой фразы + речь + хвост: 5 с тишины + «да» 0.6 с → окно 6.4 с,
   пометка есть, эмбеддер получил 90 % тишины. Правка: минимум по секундам речи VAD.
7. **[high]** `dictate.py:328` — провал `open` с `voice` (нет персоны; `Model.from_pretrained`
   бросил — нет кэша/сломан torch) не создаёт сессию, следующий `audio` создаёт сессию **без**
   маркера → все фразы «?» → канал `me` → суфлёр молчит весь звонок; приложение видит только
   строку в логе. Правка: `open` отвечает `ack`/ошибкой, приложение показывает состояние
   «пометки выключены» и не открывает канал молча.
8. **[medium]** `dictate.py:214` — сторож отставания сравнивает wall-clock от первого кадра с
   `received/sr` без ресинхронизации: после дыры в звуке (пересборка микрофона сторожем 4 с)
   `_behind()` остаётся `True` до конца звонка — промежуточных разборов нет, только
   overflow-закрытия по 18 с. Правка: ресинхронизировать по дыре или считать отставание от
   последнего принятого кадра.
9. **[medium]** `dictate.py:316` — загруженный `LiveVoice` кешируется на весь процесс
   (≥ 300 с idle, через звонки): удалил образец / записал эталон заново → следующий звонок
   считает по старым векторам. Правка: перечитывать образцы на каждом `open` (дёшево) или
   сбрасывать кеш по mtime базы.
10. **(воспроизведено, флаг спорный)** `dictate.py:226` — одна метка на VAD-окно до 18 с: две
    реплики в одной паузе < 0.8 с эмбеддятся вместе и получают жёсткое «Я / не я»; обещанного в
    §8 «?» для смеси в коде нет. Правка: дорожки говорящих внутри окна (RESULT.md §3).

## Находки: подсказчик

11. **[high]** `PrompterController.swift:136` — `lastSentID`/`lastSentAgenda` живут весь сеанс
    приложения (один `CallController` на всё время, `AppDelegate.swift:815`): второй звонок без
    перезапуска MLaud — суфлёр не получает строк (id нового `LiveTranscript` начинаются с 1 и
    меньше `lastSentID`). Правка: сброс в `prepare()`/`clearCall()`; тест «два звонка подряд».
12. *(= находка 4, найдена вторым ревьюером со стороны подсказчика; здесь для полноты.)*
    `PrompterController.swift:141`, `CallController.swift:180` — ретро-исправление уже
    отправленной строки не доходит до модели.
12а. **[medium]** `orchestrator.py:501` — `_retry()` из `tick()` игнорирует `paused_user`,
    `finishing` и потолок: ход получил 5xx → пользователь нажал «Пауза» → через 5 с запрос
    уходит на паузе. Правка: `_retry` под те же гейты, что `_maybe_fire`.
13. **[medium]** `PrompterPolicy.swift:50` — статус `.cards`/`.warm` безусловно ставит `.ready`
    поверх `.pausedByUser`, а флаг паузы в `AppDelegate` — тумблер без сброса: кнопка «Пауза»
    после прихода карточек снимает паузу. Правка: пауза — отдельное поле состояния, не статус.
14. **(воспроизведено, флаг спорный)** `orchestrator.py:371` / `_lose_turn` (:222–229) — после
    потери хода (3 неудачи или два битых JSON) реплики возвращаются в копилку с
    `pending_reason = "them_phrase"` и `_after_flight(lose=True)` тут же стреляет снова:
    модель, всегда отдающая не-JSON, дала 43 запроса / 22 хода за 200 с с начислением стоимости;
    `MAX_ATTEMPTS` ничего не ограничивает, тормозят только RPM и потолок. Правка: после потери
    хода — пауза (backoff) и лимит потерь подряд, затем `paused` с сообщением.
15. **(воспроизведено, флаг спорный)** `providers.py:63` — потолок стоимости молча не работает у
    подключения без цен и без `usage.cost` шлюза: `estimate_cost` → `None`, `cost_total` = 0,
    пауза по потолку не наступает (OpenRouter `usage.cost` отдаёт — дефолтное подключение
    защищено; пользовательское без цен — нет). Правка: без цен и без `usage.cost` — считать
    по токенам с предупреждением или отказываться стартовать с потолком.

## Находки: документы против кода

16. **[high]** `worker/README.md:230`, план :82–94, `livevoice.py:35–37`, `CallScreen.swift:126`
    — диагноз 0.13.5/0.13.6 («начитка и разговорная речь — ортогональные режимы», «пишите
    эталон с обычного места») неверен: расхождение — гейт микрофона и эмбеддинг сырых окон
    (RESULT.md §1–2). Пользователь, следующий инструкции, получает чистый эталон, к которому
    окна с нулями дают 0.09–0.3 → свои реплики «не я». Документы править вместе с кодом.
17. **[high]** `dictate.py:222` против `livevoice.py:3`, README:220, feature-prompter.md:632 —
    «фраза ≥ 2 с» на деле «окно VAD ≥ 2 с» (см. 6).
18. **[medium]** `CallController.swift:596` против feature-prompter.md §4.4:341–343 — обещание
    «t0/t1 совпадают с .m4a и после перезапуска» офлайн-веткой не выполняется (см. 1).
19. **[medium]** `test_livevoice.py:164` — план 5.1 обещает `skipif`-тест «воспроизвести таблицу
    «Я / не я» из S4»; `test_s4_table_reproduced` проверяет только `THRESHOLD == 0.60`.
    Переход на best-of-refs прошёл зелёным. Правка: настоящий регрессионный прогон на
    `~/ASR/spkid-eval` (клипы, а не окна) и отдельный — на окнах реальных звонков.
20. **(воспроизведено, флаг спорный)** README:221–222 и др. — «71 % своих / 0 ложных «Я»»
    заявлены как свойство живого маркера; измерено на чистых клипах диаризации и для одного
    центроида, живой путь это не воспроизводит (RESULT.md §3: вариант A — 1/5 ложных).
21. Приёмка этапа 5 неизмерима по журналу: нет секунд речи, `window_sec/reason`, победившего
    образца, истины «кто говорил»; `t0/t1` не выровнены с `.m4a` (см. 1) — автосверка с
    пакетной диаризацией после звонка невозможна. Правка — RESULT.md §4 п. 2 и 4.

Отброшено ревьюерами как не дотягивающее до планки (не проверялось повторно): `detail` по
закреплённой карточке молчит; дубли строк в ВКС из-за `lastSentID` по порядку `t0`; эхо
собственных правок повестки модели; `finish` при `.failed` ждёт 45 с; неудачный прогрев не
повторяется; накопление хвоста «Я» (вошло в 3); `enroll-reference` наследует
`MLAUD_NUM_SPEAKERS` и может порезать одноголосый эталон на два кластера; баннер «все реплики
будут «Я»» (на деле «?»); устаревшие 1.5 с / имена / «Гость» в FR-12.12 и ADR-025.
