# Спайк: «Я / не я» на одном микрофоне — почему не работает и что чинит. Результат

**Дата:** 2026-09-13 · **Вопрос:** живая пометка говорящего в офлайн-режиме суфлёра (этап 5)
на реальных звонках даёт случайные метки («0.81 ↔ 0.09 внутри одного звонка», 0.13.5).
Скрипт — [eval.py](eval.py); данные — офлайн-звонки 12–13.09 из архива, окна фраз — из
`transcript.live.jsonl` папок звонков, правда о говорящем — по содержанию реплик.
Модели те же, что в конвейере: `wespeaker-voxceleb-resnet34-LM` (эмбеддинг),
`pyannote/segmentation-3.0` (VAD и дорожки говорящих), обе в кэше.

**Вердикт: задача решаема, предел не в модели. Сломаны две вещи: (1) микрофонный тракт
MLaud отдаёт звук, обработанный гейтом — 48–65 % сэмплов записей звонков это точные
цифровые нули, а речь собеседника с другого конца стола подавлена до −44 dBFS и ниже;
(2) маркер эмбеддит сырое окно вместе с нулями, а «разговорный» эталон «Я» (0.13.5)
снят с такого же окна — это отпечаток гейта, а не голоса, и после перехода на «лучший
из образцов» (0.13.6) любое почти пустое окно становится «Я». По речи, вырезанной
VAD-моделью, голос пользователя между звонками даёт косинус 0.72–0.83, гость А — ≤ 0.20,
гость Б — ≤ 0.17; на живых окнах с ≥ 1.5 с речи эталон «начитка» с порогом 0.40–0.45 даёт
16/16 своих окон «Я» и 0/5 ложных «Я». Удалённая в 0.13.4 персона «я» из замера S4 —
голос пользователя (0.42–0.66 по чистой речи; гость А 0.10): удаление было ошибкой.
Из бэкапа `~/ASR/voices-backup-20260913.tar.gz` нужно **импортировать 11 образцов в персону
«Я»** (скопировать `.npy`/`.json` и записать их в `index.json`), а не распаковывать архив поверх
базы: снимок сделан в 16:52, до создания «Я» и её образцов, и затёр бы их; отдельную персону
«я» маркер игнорирует, пока есть точная «Я» (`self_refs`).**

У встроенного микрофона без обработки шумовой пол −60 dBFS и нулей не бывает. Точные
нули между словами и подавленные дальние голоса — почерк шумоподавления/изоляции голоса.
Гейт стоит с первого дня, за который есть захваты MLaud: в стерео-записях ВКС-звонков
6–8.09 (левый канал = микрофон) нулей 7.5–91 % (медиана по 13 файлам ≈ 42 %), в записях
с iPhone за те же дни (2–10.09, 32 кГц) 0.0–0.4 % и пол −43…−60 dBFS. Захватов микрофона
MLaud раньше 6.09 в архиве нет (диктовка не пишет файлов), поэтому «когда включили режим»
по записям не узнать.
Попутно: и пакетная диаризация (`pyannote 3.1`) на этих файлах ошибается — в 17-14-06 и
17-32-03 голос пользователя разрезан на двух «Спикеров», в звонках 12.09 гость А и гость Б
слиты с «Я».

**Откуда гейт.** Проба [poc/appaudio](../appaudio/) с режимом `miccompare` (сборка 170001,
8 с комнатной тишины, тот же `AVCaptureSession` с теми же `audioSettings`, что у
`MLaudCore/AudioCapture.swift`, и параллельно сырой `AVAudioEngine`):

| тракт | нулевых сэмплов | серий ≥ 100 мс | пол/медиана/пик, dBFS |
|---|---|---|---|
| AVCaptureSession 16 кГц int16 | 2.3 % | 1 (0.1 с) | −61 / −58 / −55 |
| AVAudioEngine сырой 48 кГц | 0.0 % | 0 | −60 / −58 / −55 |

Режим микрофона пробы (`AVCaptureDevice.activeMicrophoneMode`) — 0, «Стандартный», до, во
время и после захвата. То есть сам `AVCaptureSession` в стандартном режиме не гейтит.
Режим микрофона в macOS выбирается в Пункте управления **на каждое приложение** и
запоминается; MLaud его никогда не читает и не пишет в журнал. Самое вероятное
объяснение — для MLaud выбрана «Изоляция голоса» (её описание — «выделяет ближний голос»;
измеренный факт про гостя Б только один: речь ниже RMS 0.006 при 5.5 с речи по VAD).
Прямо это не проверено: режим виден только из самого процесса MLaud — первое, что нужно
добавить в приложение, это строка `режим микрофона: …` в журнал рядом с «вход: …», а
пользователю — посмотреть Пункт управления → Режим микрофона во время захвата MLaud.

## 3. Живые окна: варианты решения

Окна — ровно те, что закрывал распознаватель в звонках (t0/t1 из `transcript.live.jsonl`);
правда — по содержанию (окна, где говорящий неясен — гость А и гость Б
говорили параллельно, — не считаются). Варианты:

- **A** — код 0.13.6: сырое окно → лучший косинус по текущим образцам «Я» («разговорные
  фразы», «начитка»), порог 0.60, окно ≥ 2 с;
- **A0** — код 0.13.3: сырое окно → центроид «я» из S4, порог 0.60;

Почему у A «19/26» — не заслуга: свои окна с 0.1–1.0 с речи получают 0.82–0.90 («Угу»,
«Скажи», «реплика»), окно гостя А с 2.5 с речи — 0.70, окно пользователя с 5.3 с

## 4. Решение

1. **Тракт.** Читать `AVCaptureDevice.activeMicrophoneMode` при старте захвата, писать в
   журнал рядом с «вход: …»; если не «Стандартный» — предупреждение на экране звонка и
   в записи эталона («Пункт управления → Режим микрофона → Стандартный», можно открыть
   `AVCaptureDevice.showSystemUserInterface(.microphoneModes)`). Запись эталона и звонок
   при «Изоляции голоса» бессмысленны: дальний собеседник подавлен. Позже — сырой тракт
   (AUHAL/AVAudioEngine с явным форматом входа), которому режимы не указ; ловушка AirPods
   24 кГц (42efd9d) там решается чтением формата устройства, а не выводом.
2. **Маркер** (`livevoice.py`): на закрытом окне — `segmentation-3.0` → кадры речи и
   дорожки говорящих; эмбеддить только речь; минимум **1.5 с речи**, а не 2 с окна;
   окно с двумя дорожками делить на две реплики (каждая — своя пометка), а не
   усреднять; в `transcript.live.jsonl` писать секунды речи и косинус.
3. **Эталоны.** Импортировать 11 образцов «я» из бэкапа в персону «Я» (не распаковывать архив
   поверх базы — снимок старше «Я»), удалить «разговорные фразы 10–24 с»; `enroll-reference` эмбеддит только речь по VAD; матчинг — центроид по каналам
   плюс «начитка». Порог стартовый **0.45** (0.40–0.45 здесь; в S4 на чистых клипах медиана
   своих 0.71) — перемерить на чистом тракте.
4. **Приёмка** — одна встреча вдвоём при стандартном режиме микрофона, с журналом секунд
   речи и косинусов: ожидание ≥ 90 % своих окон с ≥ 1.5 с речи помечены «Я», ложных «Я» —
   0. Только после этого — двухклассовое решение (косинус к «Я» против онлайн-центроида
   собеседника плюс инерция «кто говорил только что») для коротких реплик.

Не измерено: чистый тракт (нет ни одной записи MLaud без гейта), перекрытие голосов
(в окнах ≈ 0 % кадров с двумя одновременными говорящими), голоса, похожие на свой, кроме
гостя А (0.09–0.20 — сходство голосов здесь не мешает).
