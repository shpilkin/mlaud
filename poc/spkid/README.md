# Замер: работает ли узнавание голоса между файлами

Проверка перед Фазой 3 ([docs/feature-speaker-id.md](../../docs/feature-speaker-id.md)).
Отвечает на один вопрос: **расходятся ли «тот же человек в другом файле» и «другой человек»
настолько, чтобы построить порог?** Если нет — ни база голосов, ни UI не помогут.

Замер использует эмбеддинги, которые диаризация и так считает
(`return_embeddings=True`, модель `pyannote/wespeaker-voxceleb-resnet34-LM`) —
вторая модель и второй прогон аудио не нужны.

## Три шага

```bash
HF_HUB_OFFLINE=1 poc/.venv/bin/python poc/spkid/extract.py     # 1. посчитать центроиды + нарезать образцы
poc/.venv/bin/python poc/spkid/label_server.py                  # 2. открыть http://127.0.0.1:8765 и разметить
poc/.venv/bin/python poc/spkid/analyze.py                       # 3. отчёт
```

Шаг 1 возобновляемый: файл с готовым `data/<slug>.json` пропускается, прогон можно прервать.
Шаг 2 сохраняет после каждого изменения — вкладку можно закрыть в любой момент.

## Данные

Всё в `~/ASR/spkid-eval/` — **локально, вне репозитория и вне iCloud**: это голоса реальных
людей, то есть биометрия.

| | |
|---|---|
| `data/<slug>.npy` | центроиды кластеров (N, 256), порядок = `speakers[].index` |
| | `<slug>` = имя файла + хвост хеша пути: APFS регистро-нечувствительна, и «планёрка.mp3» с «Планёрка.m4a» иначе схлопываются в один json |
| `data/<slug>.json` | длительность, частота/каналы исходника, кластеры, ссылки на образцы |
| `clips/<slug>/` | по 3 фрагмента ×6 c на кластер, разнесённые по таймлайну |
| `labels.json` | твоя разметка: имя на кластер + тип канала на файл |
| `report.md` | результат шага 3 |

Удалить всё: `rm -rf ~/ASR/spkid-eval`.

## Что меряется

- **Кросс-файловые пары.** Пары внутри одной записи, сохранённой дважды (совпала
  длительность), исключаются: там аудио почти идентично и оценка получилась бы завышенной.
  Пары внутри одного файла тоже не считаются — кластеризация их уже развела, это лёгкий случай.
- **EER и порог при заданной доле ложных принятий** — цена вопроса в обе стороны.
- **Leave-one-file-out.** Галерея из всех файлов кроме проверяемого, матчинг кластеров
  проверяемого. Прямая симуляция боевого режима, включая случай «голоса нет в базе»:
  человек, встретившийся ровно в одном файле, при проверке этого файла становится
  неизвестным, и правильное поведение — отказ, а не имя.
- **Разрез по каналам** (телефон↔телефон, ВКС↔ВКС, телефон↔ВКС) — отпечаток, снятый на одном
  канале, может не узнаваться на другом.
- **Отдельно свой голос** — главный сценарий, и по нему больше всего данных.

## Разметка: что важно

- Одинаковое имя в разных файлах = один человек. На этом держится весь замер.
- Кнопка «смесь» — если в кластере слышно двоих. Такой кластер исключается: диаризация
  слила людей, и центроид смешанный; засчитать его за одного человека значит испортить
  оба распределения.
- Не узнал голос — оставь пустым, кластер просто не участвует.
- Короткие файлы (< 60 c) шаг 1 пропускает: центроид из нескольких секунд речи — шум.
