# MLaud — личный аналог Plaud на iPhone + Mac

Самодельная замена устройству/сервису [Plaud](https://www.plaud.ai): записал голос на iPhone →
аудио автоматически транскрибируется **локально на Mac** (модель GigaAM-v3) → готовый текст
с тайм-кодами прилетает файлом в Telegram. Без подписок, без облачной транскрипции; аудио и
транскрипты хранятся **локально на Mac**.

## Зачем

Ценность Plaud — в железке (незаметное всегда-готовое устройство). Сама транскрипция — копеечная
операция. Идея проекта: воспроизвести **софтверную** часть Plaud телефоном, который и так всегда с
собой, и бесплатно транскрибировать локально на мощном MacBook (M5, 48 ГБ).

## Как это работает (в двух словах)

```
iPhone (Voice Memos → Поделиться)  ──►  iCloud (ТРАНЗИТ)  ──►  Mac: menu bar app  ──►  Telegram
        запись                           ASRInbox/AllRecords    GigaAM-v3 MLX            файл .txt+тайм-коды
                                         сразу очищается        хранит локально         + системное уведомление
```

Запись идёт через **Voice Memos → «Поделиться»** в папку (Shortcut опционален — он лишь
авто-маршрутизатор). iCloud — **только транзитная труба**: Mac забирает файл локально и удаляет из
iCloud. На Mac работает **приложение в строке меню** (.dmg): следит за папкой, переживает сон,
показывает статус, а тяжёлую транскрипцию выполняет эфемерный подпроцесс — память под модель занята
**только во время прогона**. Аудио и транскрипты хранятся **локально на Mac**.

## Фазы

- **MVP:** распознавание (GigaAM-v3 `rnnt`, максимальная точность) + тайм-коды + локальное хранение
  + доставка файлом в Telegram.
- **Фаза 2:** диаризация (pyannote) — метки «Спикер N».
- **Фаза 3:** идентификация по голосу с твоими именами (база голосовых отпечатков).
- **Сквозное:** архитектурный хук под авто-суммаризацию (пока вручную в LLM).

## Ключевые решения (кратко)

| Вопрос | Решение | Почему |
|---|---|---|
| Где транскрибируем | Локально на Mac | Бесплатно, приватно, M5 избыточно мощный |
| Движок | GigaAM-v3 (MLX-порт), вариант `rnnt` | SOTA для русского, нативно под Apple Silicon, точность в приоритете |
| Захват | Voice Memos → «Поделиться» (Shortcut опц.) | Триггер — папка, не Shortcut; Back Tap не нужен |
| Транспорт | iCloud Drive — только транзит | Развязка с офлайн-Mac; iCloud не забивается |
| Хранение | Локально на Mac (`~/ASR/…`) | В iCloud мало места; конвенция папок пользователя |
| Интерфейс | Нативное Swift-приложение в строке меню, неподписанный .dmg | Видимый статус; запуск кликом, не из терминала |
| Граница Swift/Python | worker — Python-подпроцесс | Чистое разделение, без FFI; ML-ядро остаётся на Python |
| Работа после сна | wake-событие + sweep | Подхватывает накопленное после пробуждения |
| Доставка | Telegram-бот, всегда файлом | Мгновенный пуш, файл удобнее для длинных |
| Имя файла | Авто по дате/времени | Без трения при записи |
| Тайм-коды | Обязательны (SRT/посегментно) | Навигация + база под диаризацию |
| Диаризация / голос-ID | pyannote, фазы 2–3 | В GigaAM нет; отдельный слой |
| Эмбеддинги для голос-ID | из того же пайплайна диаризации | Считаются бесплатно; вторая модель не нужна (ADR-016) |
| Жизненный цикл модели | Эфемерный процесс + watcher | RAM занята только во время обработки |

## Папки и диагностика

Всё локально на Mac:

| Папка | Назначение |
|---|---|
| `~/ASR/ASROutput/AllOutputs/<YYYY-MM>/` | результаты (`.txt`, `.srt`) по месяцам |
| `~/ASR/Processed/AllRecords/<YYYY-MM>/` | архив успешно обработанного аудио |
| `~/ASR/Failed/` | **карантин**: файлы, которые не удалось обработать (не зацикливаются на ретраях) |
| `~/ASR/service/worker.log` | лог worker'а (stdout/stderr) — открывается из меню «Открыть лог…» |

**iCloud-нюанс:** при «Оптимизации хранилища Mac» файл в inbox может быть *выгружен* (есть имя и
размер, но данных локально нет). Приложение такие файлы **пропускает и запускает их докачку**, а не
пытается прочитать «пустышку» — обработка происходит после фактического скачивания.
