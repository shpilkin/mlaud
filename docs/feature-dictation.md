# Диктовка по горячей клавише

Наговорить текст прямо в то поле ввода, которое сейчас активно — в письмо, в поиск,
в редактор. ⌃⌥D включает микрофон, ⌃⌥D выключает; слова появляются по мере речи.

## Почему это оказалось дешевле, чем выглядело

Главный вопрос был «потянет ли модель реальное время». Замеры на GigaAM-v3 RNNT (MLX,
M-серия), окно переразбирается целиком:

| окно | время разбора |
|---|---|
| 1 с | 0.05 с |
| 5 с | 0.10 с |
| 10 с | 0.17 с |
| 20 с | 0.24 с |

Запас больше чем десятикратный: на кусок в 0.4 с уходит 0.042 с по медиане и 0.20 с
в худшем случае. Узкое место не в распознавании.

Настоящая сложность — три системные вещи, и только одна из них требует разрешения:

- **горячая клавиша поверх всех приложений** — Carbon `RegisterEventHotKey`, разрешений
  не просит. `NSEvent.addGlobalMonitorForEvents` просил бы «Универсальный доступ» и до
  его выдачи молча не работал бы;
- **микрофон** — AVAudioEngine, обычный системный запрос при первом нажатии;
- **печать в чужое приложение** — вот здесь без «Универсального доступа» никак, и это
  не обойти: синтез событий клавиатуры в чужой процесс защищён именно им.

## Как устроено

```
⌃⌥D → AudioCapture (16 кГц mono int16)
         │  JSON-строки по stdin
         ▼
   python -m mlaud_worker.dictate   ← резидентный, модель уже в памяти
         │  {"t":"commit"} / {"t":"preview"}
         ▼
   TextInserter → CGEvent с юникодной строкой → активное поле ввода
```

### Резидентный процесс

Пакетный worker эфемерный: поднялся, разобрал inbox, умер. Для диктовки так нельзя —
загрузка модели это 1.8 с и ~1.6 ГБ RSS, и ждать их после каждого нажатия бессмысленно.
Поэтому распознаватель живёт отдельным долгим процессом. По той же причине он не висит
вечно: через 5 минут простоя закрывается и отдаёт память.

Протокол — JSON-строки в обе стороны, аудио внутри base64. Двоичные кадры были бы
экономнее, но 32 КБ/с речи превращаются в 43 КБ/с base64 — на фоне распознавания это
ничто, зато поток читается глазами и тестируется без Swift.

### Что печатать, а что придержать

RNNT переразбирает растущее окно целиком, и хвост при этом пляшет. Живой пример из
замера: на первой секунде модель слышит `Просто`, на четвёртой это становится
`Так, погнали.` Напечатать «Просто» и потом стирать — значит слать backspace в чужое
приложение и рисковать съесть чужой текст, если пользователь увёл курсор.

Поэтому печатается только то, что устоялось: слово уходит в поле ввода, когда оно
совпало в двух последних разборах подряд, и последнее слово всегда придерживается
(`CommitTracker`). Глубже последнего слова правки в замерах не заходили. Хвост уходит
отдельным событием `preview` — его можно показать всплывающей подсказкой, но в чужой
текст он не попадает никогда.

Плата: слово появляется примерно через секунду после того, как произнесено. Это цена
за то, что напечатанное больше не меняется.

### Конец фразы

Пауза в 0.8 с (VAD по энергии) закрывает фразу: остаток коммитится, окно начинается
заново. Плюс жёсткий предел в 18 с — gigaam режет аудио на 20-секундные чанки, до этой
границы окно доводить нельзя.

## Разрешения

При первом ⌃⌥D система спросит микрофон, а «Универсальный доступ» придётся выдать
руками: Настройки → Конфиденциальность и безопасность → Универсальный доступ → MLaud.

**Ловушка ad-hoc подписи — она сработала на живом примере.** Подпись у сборки ad-hoc
(`Signature=adhoc`, `TeamIdentifier=not set`), поэтому macOS привязывает разрешение к
хешу конкретного файла:

```
CDHash=9ad76ad7743b3f65f8b170e69a791ab9379f768a
```

После пересборки хеш другой. Галка в списке остаётся стоять — но относится к прежнему
файлу, а `AXIsProcessTrusted()` для нового отвечает «нет». Выглядит как «разрешение
выдано, но не работает». Лечение: удалить строку MLaud кнопкой «−» и добавить
`/Applications/MLaud.app` заново.

### Стабильная подпись — чем это лечится насовсем

Локальный самоподписанный сертификат вместо ad-hoc. Признак опознания меняется с
«тот же файл» на «тот же идентификатор и тот же сертификат», и пересборка разрешение
не рвёт. Проверено на двух заведомо разных двоичных файлах:

```
probe1  CDHash=826a2703…  designated => identifier "com.mlaud.app" and certificate leaf = H"…"
probe2  CDHash=02c49db0…  designated => identifier "com.mlaud.app" and certificate leaf = H"…"
```

Создание сертификата — один раз:

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout /tmp/mlaud-key.pem -out /tmp/mlaud-cert.pem \
  -subj "/CN=MLaud Local Signing" \
  -addext "basicConstraints=critical,CA:false" \
  -addext "extendedKeyUsage=critical,codeSigning" \
  -addext "keyUsage=critical,digitalSignature"
openssl pkcs12 -export -inkey /tmp/mlaud-key.pem -in /tmp/mlaud-cert.pem \
  -out /tmp/mlaud.p12 -passout pass:mlaud
security import /tmp/mlaud.p12 -k ~/Library/Keychains/login.keychain-db -P mlaud -A
security add-trusted-cert -r trustRoot -p codeSign \
  -k ~/Library/Keychains/login.keychain-db /tmp/mlaud-cert.pem
```

**Пароль контейнера обязан быть непустым.** С `-passout pass:` контейнер создаётся без
единой жалобы, а `security import` падает с `MAC verification failed during PKCS12
import (wrong password?)` — сообщение уводит в сторону, пароль тут ни при чём, macOS
просто не переваривает пустой. При этом `add-trusted-cert` отрабатывает и кладёт
сертификат в связку **без закрытого ключа**: в списке он есть, а
`security find-identity -v -p codesigning` показывает `0 valid identities`.

`build-dmg.sh` подхватывает сертификат сам, если он есть в связке (имя переопределяется
через `MLAUD_SIGN_ID`), и молча откатывается на ad-hoc, если нет.

## Если не работает

Диктовку можно запустить из меню, не трогая горячую клавишу, — так сразу видно,
что именно сломано. Работает из меню, но не по клавише — дело в сочетании; не
работает нигде — дело в разрешениях или в распознавателе.

Всё, что происходит, пишется в `~/ASR/service/dictation.log`: удалась ли регистрация
сочетания, было ли нажатие, выданы ли микрофон и «Универсальный доступ». Меню →
«Журнал диктовки…».

## Ограничения

- Печатается по-русски: модель русскоязычная, переключения языка нет.
- Пунктуация — та, что даёт модель. Голосовых команд («точка», «запятая») нет.
- Нет отмены: напечатанное убирается обычным ⌘Z в самом приложении.
