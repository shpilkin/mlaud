# Доступ агентов к MLaud по MCP

Внешний агент (openclaw и любой MCP-клиент на этом Mac) распознаёт голосовые и читает архив
транскриптов MLaud. Решение и обоснование — [ADR-027](adr.md). Код:
[mlaud_worker/mcp](../worker/mlaud_worker/mcp), [AgentAccessController.swift](../app/Sources/MLaudApp/AgentAccessController.swift).

## Включение

Настройки → «Агенты» → «Доступ для агентов по MCP». Приложение поднимает сервер на
`http://127.0.0.1:8767/mcp`, состояние видно там же и в меню. «Скопировать команду для
openclaw» кладёт в буфер готовую команду с токеном:

```bash
openclaw mcp add mlaud --transport streamable-http --url http://127.0.0.1:8767/mcp --header 'Authorization=Bearer <токен>' --timeout 900
```

`openclaw mcp add` сам проверяет подключение перед сохранением. «Сменить токен» отключает
всех подключённых агентов — их надо добавить заново (`openclaw mcp unset mlaud`, затем
новая команда).

## Инструменты

| инструмент | что делает |
|---|---|
| `transcribe` | распознать файл: `path` (абсолютный) или `audio_base64` + `filename`; `format` — `text` · `timestamps` · `srt` · `segments`; `speakers` — по спикерам; `num_speakers` |
| `list_transcripts` | транскрипты архива, новые сверху; `query` — подстрока в имени, `limit` |
| `get_transcript` | текст по `id` («ГГГГ-ММ/имя» или имя); `format` — `txt` · `srt`; `max_chars` |
| `status` | модели в памяти, файлы в inbox, недоставленное, число транскриптов |

**`transcribe` — только ASR.** Не пишет в `~/ASR`, не шлёт в Telegram, не сдаёт артефакт
в Niti. Base64 живёт во временном каталоге до конца вызова. Форматы (системный `afconvert`):
голосовые Telegram `.ogg`/`.oga` (Opus), видеокружки `.mp4`, `.mp3`, `.m4a`, `.wav`, `.aac`,
`.flac`, `.aiff`, `.caf`; `.webm` — ошибка декодирования. Имена по голосу подставляются, если
в приложении включены диаризация и «Подписывать известные голоса».

**Чтение архива** ограничено каталогом транскриптов: `id` с `..`, абсолютные пути и
символические ссылки наружу отклоняются. База голосов и сайдкары разметки агенту недоступны.

## Поведение

- **Модель по требованию.** Первый вызов грузит GigaAM (~6 с), дальше 30 с голосового —
  ~0.6 с. После 10 минут простоя модели выгружаются (замер: 1.1 ГБ → 0.24 ГБ). После
  диаризации процесс перезапускает себя, иначе torch держит ~1.2 ГБ; порт недоступен ~2 с.
- **Вызовы распознавания идут по одному.** `status` и чтение архива отвечают параллельно.
- **Жизненный цикл.** Сервер живёт, пока работает приложение и включена настройка; крах или
  `kill -9` приложения закрывает трубу, и сервер выходит. Упавший сервер перезапускается,
  но не чаще трёх раз в минуту. Занятый порт — ошибка в настройках, без повторов.
- **Смена настроек.** Диаризация, имена по голосу и папка inbox запекаются в процесс при
  запуске: их смена перезапускает сервер.
- **Журнал** stderr сервера — `~/ASR/service/mcp.log` (кнопка «Журнал»).
- **Только этот Mac.** Сервер слушает 127.0.0.1. Доступ с другой машины (Air через Tailscale)
  — отдельная задача.

## Расширение

Новый инструмент — `Tool(...)` в [tools.py](../worker/mlaud_worker/mcp/tools.py): функция
`(engine, args) -> str`, ошибка ввода — `ToolError`. Транспорт и протокол не меняются.
Модели берутся через `engine.transcriber()` / `engine.diarizer()` внутри `with engine.using():`.

## Отладка без приложения

```bash
cd worker && PYTHONPATH=. ../poc/.venv/bin/python -m mlaud_worker.mcp
```

Это stdio-режим. Проверка контроллера приложения — `MLaudApp --smoke-agents <python> <worker> <порт> [hold]`.
