# План: главное окно и суфлёр

Две задачи от 2026-09-04, в этом порядке:

1. **Главное окно** в дизайн-системе Niti для всей существующей функциональности — вместо
   пяти окон и выпадающего меню ([ux-app.md](ux-app.md)).
2. **Суфлёр**: захват звонка и встречи, живой транскрипт, подсказки по брифу, итоги
   ([feature-prompter.md](feature-prompter.md)).

Читать перед началом: оба документа выше, [feature-dictation.md](feature-dictation.md)
(резидентный распознаватель — фундамент), [task-speaker-id-v1.md](task-speaker-id-v1.md)
(образец того, как здесь принимается работа), ADR-018…026 в [adr.md](adr.md).

---

## 0. Порядок и правила

1. **Числа раньше кода.** Этап 0 — спайки; результат каждого — `poc/<имя>/RESULT.md` с
   цифрами. Этап, у которого гейт не закрыт числом, не начинается.
2. **Порядок от пользователя: сначала окно, потом суфлёр.** Экраны суфлёра строятся сразу в
   `NitiUI`, а не переносятся — они и делают набор компонентов настоящим; старые окна
   переносятся после.
3. **Логика без UI** — в `MLaudCore` (раннер `swift run MLaudTests`) и в `mlaud_worker`
   (`pytest`). Экран — тонкий: состояние приходит из тестируемых типов.
4. **Ничего существующего не ломать.** Протокол `dictate` без поля `ch` работает как раньше;
   `process_file` без сайдкара каналов — как раньше; диктовка, приём с iPhone, голос-ID —
   без изменений поведения. Старые тесты зелёные на каждом этапе.
5. **Этап заканчивается сборкой `.dmg` и живой проверкой** на этой машине. «Готово» — после
   запуска, не «должно работать».
6. Версии: 0.6.x — главное окно, 0.7.x — живой звонок, 0.8.x — подсказчик, 0.9.x —
   офлайн-режим. Коммиты — только по просьбе.

- Деградация проверена руками: без ключа, с выключенной сетью, с упавшим процессом — звонок

### Этап 5 — офлайн-режим (0.9)

- Замеры диктовки (feature-dictation.md): разбор окна 1/5/10/20 с — 0.05/0.10/0.17/0.24 с;
  AVCaptureSession против AVAudioEngine на Bluetooth; ловушка ad-hoc подписи и стабильный

  (task-speaker-id-v1.md §2); пороги 0.70/0.75/0.80 измерены (ADR-016).

  `sufler/app/Sources/Sufler/Audio/SystemAudioCapture.swift` работал в прототипе.
- Niti читает артефакт через `.get` (`email_reader/meetings.py`) — лишний блок безопасен.
- `NitiUI` (mlaud mobile) не содержит UIKit нигде, кроме динамического цвета в `Tokens.swift`.
- Локальный `llama.cpp` с Qwen3.6-35B-A3B держит 66 tok/s на генерации
  (`~/my_projects/local llm/README.md`); скорость обработки промта не измерялась.

## 3. Этап 0 — спайки

Каждый спайк — отдельная папка в `poc/`, скрипт или проба, `RESULT.md` с числами, датой и
решением. Спайки независимы, порядок любой; S1 и S5 — самые длинные, начинать с них.

### S1. Два канала в одном распознавателе (OQ-12) — ✅ сделан 2026-09-05, [poc/live2ch/RESULT.md](../poc/live2ch/RESULT.md)

- `poc/live2ch/run.py`: поднимает `dictate.serve` с расширенным протоколом (или его
  прототип в самом спайке), кормит две дорожки из архива `~/ASR/Processed` **в темпе
  реального времени** (кусками по 0.1 с с ожиданием), одновременно, 5 минут непрерывной речи
  на обоих каналах.
- Метрики: отставание (секунды принятого звука минус разобранного) по каждому каналу во
  времени; задержка от закрытия фразы до события `phrase`; время разбора на тик.
- Варианты: каденс 0.4 с фиксированный; каденс, растущий с длиной окна (0.4 с до 5 с окна,
  далее пропорционально); окно 18 с и 12 с.
- Гейт: отставание не растёт (≤ 1 с на протяжении всего прогона), задержка `phrase`
  ≤ 1.5 с. Если не держит — решение между очередью декодера с приоритетом канала
  собеседника и вторым процессом; по числу.

### S2. Звук приложения звонка (OQ-13)

- `poc/appaudio/` — Swift-проба уровня `etap0/AudioProbe` прототипа, две ветки:
  (а) process tap на выбранный PID (`CATapDescription`, `AudioHardwareCreateProcessTap`,
  агрегатное устройство, IOProc), (б) ScreenCaptureKit с фильтром по приложению.
- Проверить: какое разрешение спрашивает система и как оно называется в настройках; попадает
  ли в захват музыка из другого приложения; формат и частота; поведение при смене устройства
  вывода (наушники ↔ динамики) и при закрытии приложения звонка; нагрузка.
- Собрать пробу как `.app` с сертификатом `MLaud Local Signing`, пересобрать, убедиться, что
  разрешение осталось.
- Гейт: хотя бы один вариант даёт изоляцию по приложению и переживает пересборку. Попутно
  зафиксировать эхо на динамиках (для предупреждения FR-12.1).

### S3. Оболочка (OQ-14)

- (а) `NitiUI` на macOS: добавить платформу в `Package.swift`, собрать пустой macOS-пакет,
  зависящий от него; записать список правок (цвет, типографика, `minTapTarget`, что ещё не
  собирается).
- (б) Политика активации: проба-приложение, 20 циклов «окно открыто → `.regular`, закрыто →
  `.accessory`»; проверить активацию, меню, поведение горячей клавиши и статус-иконки.
- Гейт: список правок для (а) конечен и не трогает публичные имена; для (б) — либо работает
  без застреваний, либо решение «всегда `.regular`».

### S4. Живая пометка на коротких фразах (OQ-15)

- `poc/spkid/short_clips.py`: для каждого клипа из `~/ASR/spkid-eval/clips/<slug>/` (6 с)
  посчитать эмбеддинг той же моделью (`pyannote.audio.Inference`, окно = весь клип),
  галерея — центроиды всех **других** файлов с той же группировкой, что в `analyze.py`
  (одна встреча в двух форматах — один файл). Матчинг `spkid.match` на 0.70/0.75/0.80.
- Отчёт: свой голос — доля верных «Я», доля чужих имён; остальные известные — то же; время
  эмбеддинга одного клипа на MPS и CPU.
- Гейт: свой голос узнаётся на ≥ 90 % клипов при нуле чужих имён на каком-то из порогов —
  режим v1 идёт как спроектирован; иначе сужается до «Я / не я» с тем порогом, который даёт
  ноль чужих, и это записывается в feature-prompter.md §8.

### S5. Задержка и цена первой карточки (OQ-16) — ✅ сделан 2026-09-05, [poc/prompter-latency/RESULT.md](../poc/prompter-latency/RESULT.md)

- `poc/prompter-latency/run.py`: системный промт из реального профиля, брифа и материалов
  на ~30 тыс. токенов (описание продуктов из папки прототипа подходит), беседа из 10 ходов с
  кусками расшифровки из архива, структурированный вывод по схеме карточек.
- Кандидаты — **решение пользователя 2026-09-05: только DeepSeek V4 Flash и GLM-5.3 Flash**
  (через OpenRouter и RouterAI; ключи пользователь дал для спайка, подключения Niti из сессии
  не расшифровываются). Claude исключён целиком как дорогой; локальный
  `llama.cpp` отложен до отдельной просьбы. Первоначальный список (`claude-opus-5`,
  `claude-sonnet-5`, локальный Qwen) в силе не остаётся. Варианты на модель: как есть, без
  рассуждений (`reasoning: {enabled: false}`), коротко (без `detail`, ≤ 3 карточек,
  повестка только изменениями) — в стриме, с замером первого токена и первой целой карточки.
- Метрики по каждому: задержка полного ответа на ход (медиана, максимум), стоимость хода
  по `usage`, стоимость часа при 12 ходах/час; для локальной — время обработки промта и
  память.
- Гейт: кандидат с медианой ≤ 3 с — модель по умолчанию. **Итог:** гейт не взят никем;
  DeepSeek V4 Flash через OpenRouter (3.4 с) принят по умолчанию как единственный рядом с
  коридором, GLM-5.3 Flash с `effort: low` — второе подключение. Замер шёл OpenAI-совместимым
  HTTP через шлюзы с автоматическим кэшем на стороне провайдера; явных точек кэша, как в
  нативном API Anthropic, в этом пути нет. Таблица — в `RESULT.md`, оттуда — в настройки.

Все семь приняты 2026-09-05. Ниже — как было поставлено и что решено.

1. ~~**`NitiUI`: общий пакет с платформенными ветками или копия в `app/`.**~~ → **общий пакет**

   названо в плане, есть уже в 14.2 (process taps), 15 снимает `#available` для поколения
   SwiftUI 2024; API выше 15 план не называет. Поднять выше при первой же нужде разрешено —
   это правка одной строки в `Package.swift` и `build-dmg.sh`, не новое решение.
3. ~~**Иконка в Dock** — по S3.~~ → ответ пользователя «иконка пусть та же остаётся» — про
   картинку: `AppIcon.icns` не меняется (задача 1.13). Присутствие в Dock (политика
   `.accessory` ↔ `.regular`) остаётся за S3, как и было.
4. ~~**Клиент модели в Python-резиденте против Swift.**~~ → **Python-резидент** (ADR-024).
5. ~~**Модель по умолчанию**~~ → решено S5 и подтверждено: **DeepSeek V4 Flash через OpenRouter**
   по умолчанию, рассуждения выключены, короткий ответ, стрим; модель **меняется в настройках**
   — список подключений с одним «по умолчанию», предустановлены DeepSeek и GLM-5.3 Flash
   (`effort: low`), бриф может переопределить (FR-12.13, задача 4.12).
6. ~~**Порядок этапов**~~ → как предложено: «окно → голоса → звонок → подсказчик → офлайн».
